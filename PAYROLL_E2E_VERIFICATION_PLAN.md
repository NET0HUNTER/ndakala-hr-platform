| **F5-1** | **Frontend Field Mismatches (`PayrollView.jsx`, `PayslipModal.jsx`)** | `PayrollView.jsx` reads `run.totalPaye` (model field is `totalPAYE`), checks status `'REVIEWED'/'SUBMITTED'` (actual is `'UNDER_REVIEW'`), and in payslips table reads `ps.employee?.fullName` / `ps.payeTax` / `ps.nssfDeduction` / `ps.housingLevy` (actual values live in `ps.employeeName` and `ps.lineItems` `PAYE` / `NSSF_EE` / `SHIF_EE` / `AHL_EE`). `PayslipModal.jsx` reads `slip.totalDeductions` and `slip.totalEmployerCost` instead of `slip.totalEmployeeDeductions` and `slip.totalEmployerCosts`. | Map exact `PayrollRun`, `PayrollSlip`, and `lineItems` fields; support both new and legacy property names cleanly in `PayslipModal.jsx`. |
| **F5-2** | **Fine-Grained RBAC Gating & 403 Avoidance (`PayrollView.jsx`, `App.jsx`)** | `App.jsx` fetches `/api/v1/payroll/runs` unconditionally on login even when the user lacks `payroll.reports.view` (`employee`, `line_manager`), causing noisy 403s. `PayrollView.jsx` uses coarse `canManagePayroll`, exposing `Calculate`, `Submit`, `Approve`, `Lock`, `Bank EFT`, and `Adjust` to `hr.lead` (who only holds `payroll.review`, `payroll.reports.view`, `payroll.config.manage`) and hiding Maker-Checker preparer separation. | Gate `/api/v1/payroll/runs` fetch on `payroll.reports.view`; introduce fine-grained flags (`canPreparePayroll`, `canReviewPayroll`, `canApprovePayroll`, `canLockPayroll`, `canExportPayroll`, `canAdjustPayroll`, `canManagePayrollConfig`, `canViewPayrollReports`); show disabled/tooltip or hide unauthorized actions cleanly. |
| **F5-3** | **Org Payslips Inspection Missing in UI (`PayrollView.jsx`)** | Admins/HR/Partners can only see `payslips` (`/slips/me` personal slips) and cannot browse all employee slips generated by a `PayrollRun` (`GET /api/v1/payroll/runs/:id/slips`). | Add **View Slips** button per `PayrollRun` (for `payroll.reports.view`) displaying employee payslip breakdown and opening `PayslipModal`. |
| **F5-4** | **Period Selection, Allowances & Bank EFT Export (`service.ts`, `PayrollView.jsx`)** | Initiating a run always uses `payPeriods[0]` instead of the user-selected period; salary assignment UI only submits `BASIC` without `HOUSE_ALLW`/`COMMUTER_ALLW` or inspecting current employee salary (`GET /payroll/salaries/employee/:id`); Bank EFT expects `res.csvContent` whereas `exportBankSchedule` returns `{ scheduleRows, fileChecksum, notice }`. | Add Period selector to **Initiate Payroll Run**; expand Salary Assignment with `HOUSE_ALLW` + `COMMUTER_ALLW` + live salary lookup; emit `csvContent` + `fileName` from `exportBankSchedule` and render export confirmation/checksum card in UI. |
| **F5-5** | **PAYE Simulator Accuracy & RuleSet Draft Proposal UI (`PayrollView.jsx`, `service.ts`)** | Calculator uses flat `25%` PAYE estimate and Year 3 NSSF `4,320` cap instead of Kenya 2026 progressive rules (`NSSF` `6,480` cap, `AHL` deductible, `SHIF` 15% relief, 5 PAYE bands). `StatutoryRuleSet` tab cannot propose a new draft rule set (`POST /payroll/rule-sets`) in UI to exercise RuleSet Maker-Checker. Also `createAdjustmentRun` uses `parentRun.runNumber + 1` which collides if multiple adjustments occur on earlier runs. | Align live calculator formula to Kenya 2026 rules + display full breakdown when **Run Backend Tax Engine** (`/payroll/simulate`) executes; add **Propose Draft Rule Set** form in `rulesets` tab; compute `max(runNumber) + 1` in `createAdjustmentRun` and allow `payroll.review` on `/runs/:id/submit`. |
